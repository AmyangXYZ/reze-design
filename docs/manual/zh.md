# Reze Design 使用手册

[English](https://github.com/AmyangXYZ/reze-design/blob/main/docs/manual/en.md) · **简体中文**

Reze Design 在浏览器里编排、渲染和发布 MMD 场景。它直接读取 MikuMikuDance 社区自
2008 年以来积累的模型与动作，用 WebGPU 渲染，最终产出一个视频文件，或者一个任何人都
能打开并自由转动视角的实时页面。

**第 0 节**是背景，写给完全没接触过 MMD 的人。**第 1 节**是完整流程，从空场景一路走
到发布。**第 2 节**讲如何做出自己的风格——调色预设、用 WGSL 写的背景特效，以及用节点
搭建的材质着色图。[附录 B](#附录-b-去哪里找模型动作和音乐) 列出模型、动作与音乐的
来源。

# 0. 关于 MMD

MikuMikuDance（**MMD**）是樋口優开发的免费 3D 动画软件，2008 年 2 月发布，最初用来让
初音未来跳舞。围绕它长出来的，是一套**可自由拼装的生态**：模型是一个人做的一个文件，
舞蹈是另一个人做的另一个文件，镜头轨迹是第三个文件，它们能拼在一起，只因为所有人都
遵守同一套骨骼命名约定。一支成品 MMD 视频往往是五到十五位素未谋面的作者共同的成果
——这正是「借物表」成为社区文化的原因，也是 2011 年的动作文件今天依然能用的原因。而
软件本身是一个 32 位、基于 DirectX 9 的 Windows 程序，开发在 2010 年代后期停止，手机
和平板完全无缘；想要现代渲染的人转向了 Blender 或 Unity，那里渲染效果出色，但可拼装
性止步于导入这一步：转换过的资产和手工重建的材质，已经不再是别人能直接拿走的零件了。

MMD 带火的这种画面风格如今已经进入主流。原神、深空之眼、鸣潮都把 3D 角色渲染成手绘
2D 动画的观感——也就是常说的**三渲二**——每一部都带着一个庞大的同人社区，产出海量二次
创作，其中相当一部分仍然由 MMD 模型和动作完成。WebGPU 让这种风格真正能在浏览器里跑起
来；而浏览器作为目标平台，早已有人认真耕耘：
[**babylon-mmd**](https://github.com/noname0310/babylon-mmd) 把 PMX 模型、VMD 动作、
物理和 MMD 兼容着色带进了 Babylon.js，至今仍是「网页上的 MMD 能做到什么」的参照。
[**reze-engine**](https://github.com/AmyangXYZ/reze-engine) 走的是另一条路：为 MMD
专门编写的渲染器，而不是架在通用引擎之上。引擎上有两个应用——**Reze Design**，也就是
本手册所讲的，用于设计、渲染与发布场景；以及
[**Reze Studio**](https://github.com/AmyangXYZ/reze-studio)，带时间轴、摄影表和贝塞
尔曲线编辑的动画编辑器。两者都能在任何装有现代浏览器的机器上运行，直接读取生态里现
成的文件，并把一个场景变成一条别人可以打开、转动、继续做下去的链接。

# 1. 做一个场景

## 1.1 整体流程

一个场景是一遍做完的，顺序并不严格，重要的是每一步都可逆：所有设置始终是活的，直到
导出前什么都没有烘焙。

> 载入模型 → 给它动作 → 加音乐 → 定镜头 → 打光 → 选风格 → 导出视频，或发布场景。

本节按这条主线展开。一望即知的控件——文件选择、色块、播放键——不再赘述；
[附录 A](#附录-a-控件速查) 列出了每个控件及其取值范围。

你需要一个支持 WebGPU 的浏览器：Chrome / Edge 113+，或 Safari 26+。编辑器提示无法启
动时，基本都是这个原因。工作过程中不会上传任何东西，文件只留在这个标签页里，直到你
主动发布。

## 1.2 模型、动作、音乐

打开 **Assets** 载入模型，可以选包含 `.pmx` 的整个文件夹，也可以直接选下载来的
`.zip`。两种方式都支持拖放。

| 格式 | 是什么 |
| --- | --- |
| `.pmx` | 模型：网格、材质、贴图、骨骼、物理 |
| `.pmd` | 早期模型格式，请先用 PMX Editor 转换为 PMX |
| `.vmd` | 关键帧。同一个扩展名既可能是**身体动作**，也可能是**镜头动作**，它们载入到不同的槽位 |
| `.fx` | MikuMikuEffect 的 DirectX 9 特效。这里对应的是[背景特效](#23-用-wgsl-写背景特效)和[着色图](#24-材质着色图)，用 WGSL 编写 |

**保持模型文件夹完整。** PMX 用相对路径引用贴图，单独把 `.pmx` 拎出来载入，模型就会
是白的或灰的。这是初次使用时最常踩的坑。

把身体动作载入同一个槽位，播放条就会出现，按播放即可。再加一个模型，它会拿到自己的
槽位和自己的动作，而全体共用一个镜头、一套灯光和一套风格。音乐绑定在时间轴上，拖动
进度和循环都会带着音频一起走。动作是针对标准骨骼编写的，因此能驱动任何模型——身材比
例差得多时会看到脚下打滑或悬空，换一个体型更接近原作者所用模型的角色即可解决。

头发和裙摆是物理模拟的，跳转后需要几帧才能稳定下来。这段抖动不会出现在导出的文件里，
因为导出器会先渲染一段预热再开始录制。

## 1.3 镜头

左键拖动旋转，右键拖动平移，滚轮缩放。

大部分公开发布的舞蹈动作都附带一份**镜头动作**——另一个 `.vmd`，装着编舞者自己的运
镜。把它载入 **Assets → Camera**，画面就会完全按作者的设计走，此时鼠标不再参与；播放
条上的开关可以随时把控制权交还给你，而播放不会中断。

需要手动构图时，**Scene → Camera** 比鼠标精确。最常用的是 Target Y：角色身高约为 10
个单位，所以目标高度接近 10 时是脸部特写，接近 5 是半身，为 0 则是贴地仰拍。

## 1.4 灯光

灯光由三个部分组成，真正需要斟酌的决定并不多。

**Sun** 是主光，阴影贴图与它的照射方向一致，所以明暗和投影永远吻合。**Elevation** 是
最具表现力的那一项：低角度带来长投影和强烈的轮廓分离，高角度让人物变平、投影缩到几
乎没有。

**World** 是环境补光——太阳照不到的地方。强度为 0 时背光面会全黑，太高则画面发平。多
数风格会用冷调环境配暖调主光，或者反过来；主光与补光之间的**色彩对比**，比任何一方
单独的强度都更起作用。

**Bloom** 是高光溢出。强度为 0 即关闭，此时整个 pass 会被跳过。阈值接近 1.0 只让真正
的高光发光；降到 0.3 附近整幅画面都会起雾，这是一种强烈而明确的取向。

**Ground** 有一点值得单说：不透明度会让地面淡出，而阴影仍然保留。不透明度为 0 且阴影
开启，你就得到了一块「影子接收板」——角色的影子浮在背景上，没有地面平面去和照片背景
打架。

## 1.5 角色背后的层

从后往前四层：**背景色**，然后是 **backdrop**（一张平铺在场景之后的图）或 **skybox**
（2:1 等距柱状全景，投影成无限远的天穹，随镜头转动，转动视角就像望向真实环境），最后
是**背景特效**——绘制在背景与角色之间的一段着色器：雨、星、飘落的花瓣、极光。

在 **Scene → Background** 里挑一个，或打开库查看全部。自己写的方法见
[§2.3](#23-用-wgsl-写背景特效)。

## 1.6 风格

两套系统决定画面的观感，它们作用在不同的尺度上。

**调色预设**变换的是整幅成品画面，在灯光之后、导出之前。它就是「渲染出来」和「看起来
对了」之间的差别：同一个场景，调暖调亮像夏日午后，调冷并压暗暗部就成了夜晚。**Scene
→ Grade** 提供内置预设——*Neutral*、*Bloody*、*Cyberpunk*、*Divine*、*Moonlit*、
*Sakura*——强度滑杆**按预设分别记忆**，来回试几种风格再切回去，会恢复你为它选定的强
度。自己做的方法见 [§2.2](#22-调色预设)。

**样式组**决定表面如何响应光照，这部分在 MMD 里没有对应概念：

> **样式组**是一组共用同一种外观的材质，**着色图**是定义这种外观的程序。每个样式组恰
> 好使用一张着色图。

一个 PMX 模型通常有十到六十个材质——脸一个、头发一个、服装好几个。逐个设置无法忍受，
所以载入时会按名称和属性自动归组：头发进头发组，眼睛进眼睛组，皮肤进身体组。遇到结构
特别的模型，归类可能出错，**Materials** 标签就是修正的地方——把材质拖到别的组、新建
组、隐藏多余的挂件，或者更换某一组使用的着色图。

有两个行为需要知道。当某一组的着色图与它来源的库条目产生差异时，会显示 **edited**
标记，而这份差异会随场景一起走，所以发布出去的场景能原样重现你做的东西。另外，部分组
带有**角色（role）**，影响的不只是着色——头发和眼睛有专门的 pass 处理，丝袜使用 alpha
hashing 以便多层叠加时正确排序。角色是推断出来的，这就是头发组和布料组表现不同的
原因。

一个节点一个节点地搭建着色图，见 [§2.4](#24-材质着色图)。

## 1.7 导出

**Render** 标签设定画幅与画质——从 2.39:1 宽银幕到竖屏 9:16，最高 4K——还可以设定区
间，比如只导出 `0:12` 到 `0:30`。该标签打开时，视口会叠加取景预览：框住的就是将要录
制的内容。

**Render video** 输出 60 fps 的 H.264 MP4。在 Chromium 桌面端会先让你选保存位置，然
后边编码边写入文件，因此再长的 4K 导出也不需要塞进内存。

关于导出器有两点值得知道。它是**离线**逐帧渲染的，所以导出质量与你的显示器无关，与标
签页是否在前台也无关——慢的机器产出同样的文件，只是花的时间更长。以及，录下来的就是你
当前的镜头、灯光和调色，没有第二套需要另行同步的渲染设置。

**Capture PNG** 按同样的画幅与分辨率写出单帧，水印和绿幕设置同样生效。它抓取的是屏幕
上当前这一帧的姿势，不跳转也不重置，不需要动作也能用，正是用来给待发布场景做封面图
的。封面建议用 1080p 抓取——细节丰富的场景在 4K 下可能超过 20 MB 上限。

**Green screen** 把背景换成纯 `#00FF00`，方便在别处合成，也就是 MMD PV 的经典流程。

## 1.8 发布

发布把你的场景变成一个任何人都能打开的页面——一份可以自由转动视角的实时渲染。

按下 **Share** 之前，先确认你有没有权利分享。几乎每个模型的下载包里都附着一份**利用
規約**（使用条款），其中**再配布禁止（禁止二次分发）非常常见**。发布会把你载入的模
型、动作和音频打包上传，好让场景能在别人的浏览器里渲染，而这在多数条款下属于二次分
发。导出视频则是另一回事，因为模型文件并不在视频里。条款通常还会涉及改造、R-18 表
现、政治与宗教用途以及商用。

与条款并行的是社区自己的规矩：**借物表**——列出用到的每一个模型、动作、特效和曲目及其
作者，让观众能顺着它找回制作者本人。Reze Design 要求必须填写：

```
模型：Tda式初音ミク・アペンド by Tda / 改造 by …
动作：… by …
镜头：… by …
音乐：… by …
```

除借物表外，对话框还会要求名称、简介、最多五个标签和一张封面图。进度按阶段汇报——打
包、上传、发布——失败时会指出是哪一步以及具体原因。你填的文字会随输入保存，因此中途离
开去截封面图，回来时简介还在。

结果是一条形如 `reze.design/<你的名字>/<id>` 的永久链接。真正用于解析的是那个短 id，
所以之后重命名场景、甚至重命名你自己，都不会让已经分享出去的链接失效。

## 1.9 画廊

Scene 标签下方的画廊按钮，打开的是所有人发布过的场景，可以按热门、最新、最赞、我的、
已赞浏览，并用标签筛选。

在某个场景的页面上，你可以转动视角、播放、点赞。**Open in editor** 会把整个场景带进你
的编辑器，成为**你自己的副本**——模型、动作、灯光、调色和材质分配一应俱全，可以继续往
下做。副本是独立的，发布它会创建一个新场景，原作不受影响。它的借物表会一并带过来，请
在此基础上继续补充。

账号的意义在于拥有你发布的东西。首次登录时需要**选择你的名字**，它会出现在你创建的每
一条场景链接里，且**只能设定一次**——正是这种不可变，让分享出去的链接永远有效。

## 1.10 出问题时

**模型是白的、灰的或黑的。** 贴图没找到，几乎都是因为 `.pmx` 是单独载入的。请载入整个
文件夹或原始 `.zip`。

**模型载入不了。** 确认它是 `.pmx` 而不是 `.pmd`；旧模型请先用 PMX Editor 转换。

**动作在播放，模型却不动。** 动作载入到了别的模型槽位，或者这个模型的骨骼命名偏离了标
准约定——从其他游戏转换来的模型常有此问题。

**脚下打滑或陷进地面。** 模型与动作原作者所用模型的比例不一致。

**镜头不响应操作。** 有镜头动作正在驱动它，在播放条上切回自由视角即可。

**导出有点慢。** 它在离线逐帧渲染：一段 4K 三分钟的导出就是数千张全画质图像。迭代时用
1080p 导一小段，最终再走一遍 4K。

**发布失败。** 报错会指明阶段。*打包*通常指向缺失的资源；*上传*通常是包体超过 200 MB
或网络中断；*发布*通常是登录已失效，或名称冲突。

# 2. 做出自己的风格

三个创作面，处在同一条管线的三个层级上。学习顺序随意。

## 2.1 渲染管线

知道你写的东西究竟作用在哪一层，后面的大部分内容就自然成立了。从镜头看过去，由后
到前：

```
  背景色  →  backdrop / skybox  →  背景特效 (§2.3)
                                        ↓
                                  角色，由样式组各自的
                                  材质着色图 (§2.4) 着色
                                        ↓
                                      bloom
                                        ↓
                                  调色预设 (§2.2)
                                  作用于整幅画面
                                        ↓
                                  屏幕、视频、PNG
```

因此：

- **背景特效**位于角色之后，角色会盖在它上面。
- **着色图**管的是一个模型上的一个样式组，依据的是该表面自身的数据——贴图、法线、视线
  方向。
- **调色预设**最后作用，均匀地施加于每一个像素，此时画面已经成型。

三者都**内嵌在场景文档里**，所以发布出去的场景能原样重现你的风格，无论对方有没有你用
过的预设。

## 2.2 调色预设

调色采用 **ASC CDL** 变换——美国电影摄影师协会的 Color Decision List，也就是影视后期
所依赖的那套基元。三个色调区间，每个区间有 slope、offset 和 power，通过色轮来操作。这
套词汇与其他任何调色工具都是互通的。

### 编辑器

打开调色库，在预设上悬停并选择 **Edit**，或直接从 **Scene → Grade** 编辑当前应用的预
设。编辑器背后的场景就是预览——每一次调整都实时落在你自己的角色、你自己的光照上，这是
判断一次调色是否成立的唯一可靠方式。

**Split tone**（−1 到 +1）放在最前面，是有意的——它是最能表达调色意图的单一动作，让暗
部和亮部沿冷暖轴向相反方向偏移。负值是冷暗部配暖亮部，即现代电影的「青橙」；正值反
之，暖暗部配冷亮部，读起来像烛光、日落或怀旧。

**三个色轮**——shadows、midtones、highlights——分别控制三个色调区间：

- **角度**——该区间偏向的色相。
- **离中心的距离**——偏移的程度。
- **色轮旁的滑轨**——该区间的明度。把暗部滑轨往下拉就是压黑，把亮部滑轨往上推就是
  提亮。

**Contrast**（0.5 – 1.6）以中灰为轴，**Saturation**（0 – 2）缩放色彩浓度，0 为黑白。

### 工作方法

能得到可预期结果的顺序：

1. **先修灯光。** 调色是在光给出的基础上做加法。人物看起来发平时，先调太阳仰角和环境
   光强度，再动调色。
2. **设定 split tone**，然后停一下。很多时候这一步就已经是整个调色了，后面都只是
   修饰。
3. **先用滑轨压黑或提亮，再推色相**——明暗决定比色彩决定更显眼，也约束着后者。色相一
   次只推一个区间，而且要比你以为的更克制：色轮推到一半距离，风格已经很强了。
4. **饱和度放最后**，通常是往下调；并在强度 1 的状态下判断，再回 Scene 标签设定你真正
   想要的强度。在半强度下调色容易过度。

有两个习惯很划算。**经常和 Neutral 对比**——看久了什么都会变得正常，切到 Neutral 停两
秒，就知道这次调色值不值得留下。以及**按导出分辨率来调**，因为在小窗口里看着合适的
bloom 阈值，到了 4K 可能过于容易发光。

### 保存与分享

编辑预设会生成一份属于你的**草稿**，保存在本地浏览器里，可以重命名、继续修改、应用到
任意多个场景。草稿是私有的，不会离开你的机器。

**Publish** 把草稿变成署你名字的库条目，所有人可见。含义见
[§2.5](#25-草稿发布与版本)。

## 2.3 用 WGSL 写背景特效

背景特效是一段着色器，绘制在背景与角色之间那一层。雨、雪、星空、极光、流动的渐变、一
张标题卡——任何可以由视线方向和时间逐像素算出来的东西。

库里有五个可读的范例，各自演示一种技法：*Shining Stars*（哈希网格粒子场）、*Quiet
Rain*（列状拖尾）、*REZE DESIGN*（SDF 字形加指数辉光）、*Orbiting Hearts*（隐函数曲线
描边）、*Fuji Watercolor*（分层水墨构图）。读它们是最快的入门方式。

### 契约

一个函数，这就是全部接口：

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f
```

| 参数 | 含义 |
| --- | --- |
| `ray` | 该像素的世界空间视线方向，已归一化。它**随镜头转动而移动**，因此由它算出的东西是钉在世界上的，而不是钉在屏幕上 |
| `uv` | 屏幕坐标，0 – 1，原点在**左下角** |
| `time` | 特效应用后经过的秒数 |

返回值是 **sRGB 颜色 + 直通 alpha**，其中 alpha 才是关键：它是覆盖在你身后一切之上的
遮罩。

- `alpha = 0`——透明，背景色、backdrop 或 skybox 透出来。
- `alpha = 1`——不透明，你的特效取代它身后的一切。

**叠加型**特效——雨、花瓣、火星——在笔触之间把 alpha 压在 0 附近，只在落笔处抬高。**全
屏型**特效——渐变天空、绘制背景——则处处返回 alpha 1。

### 两种取向

`ray` 还是 `uv`，是第一个决定，它决定了镜头运动时特效的行为。

**屏幕空间**，来自 `uv`——钉在画框上。无论镜头看向哪里，雨都沿屏幕落下。适合天气、暗
角、颗粒，以及一切概念上位于世界**之前**的东西。

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  // 修正宽高比，让圆是圆的。
  let res = bgResolution();
  let p = (uv - 0.5) * vec2f(res.x / res.y, 1.0);
  let d = length(p);
  let vignette = smoothstep(0.8, 0.2, d);
  return vec4f(vec3f(0.02, 0.03, 0.08), 1.0 - vignette);
}
```

**世界空间**，来自 `ray`——属于环境的一部分。转动镜头它待在原处，就像真实的天空。用与
skybox 相同的映射把视线投到球面坐标：

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  // 经纬度——skybox 自己的投影方式。
  let sky = vec2f(atan2(ray.x, ray.z), asin(clamp(ray.y, -1.0, 1.0)));
  let band = smoothstep(0.0, 0.35, sky.y);          // 地平线 → 天顶
  let dusk = mix(vec3f(0.85, 0.45, 0.30), vec3f(0.06, 0.09, 0.22), band);
  return vec4f(dusk, 1.0);
}
```

这一步要想清楚：用 `uv` 画的星星会在镜头转动时整片滑过天空，观众即使说不出原因，也会
立刻觉得不对。

### 一个完整的叠加例子

飘浮的光点，使用起始模板里的哈希辅助函数：

```wgsl
const COUNT: i32 = 48;
const FALL_SPEED: f32 = 0.04;
const RADIUS: f32 = 0.006;

fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  let res = bgResolution();
  let p = (uv - 0.5) * vec2f(res.x / res.y, 1.0);

  var acc = 0.0;
  for (var i = 0; i < COUNT; i = i + 1) {
    // 每个光点一个稳定的伪随机初始位置。
    let seed = hash2(vec2f(f32(i), 7.0));
    // 下落、到底回绕，并按各自的相位横向漂移。
    let y = fract(seed.y - time * FALL_SPEED) - 0.5;
    let x = (seed.x - 0.5) * 1.8 + sin(time * 0.6 + seed.x * 30.0) * 0.02;
    let d = length(p - vec2f(x, y));
    // 按比例衰减，任何分辨率下边缘都保持清晰。
    acc = acc + smoothstep(RADIUS, 0.0, d);
  }

  let glow = clamp(acc, 0.0, 1.0);
  return vec4f(vec3f(1.0, 0.94, 0.82), glow * 0.85);
}
```

注意这里的写法：可调参数写成文件顶部具名的 `const`；用 `fract` 让运动回绕，长镜头下不
会越积越大；边缘用 `smoothstep`。

### 编辑循环

打开 **Scene → Background → Library**，选 **New effect** 得到一份带注释的起始模板，或
右键任意预设选 **Edit shader** 来 fork 它。

**<kbd>⌘/Ctrl</kbd>+<kbd>Enter</kbd> 编译并应用。** 场景本身就是预览，没有单独的渲染按
钮，也没有预览窗口。编译成功，特效立刻生效；编译失败，先前的着色器保持不变，并给出
`行:列` 位置已重新映射到你自己代码的诊断信息，所以反复迭代不会让你面对一片黑屏。

### 规则

- **自包含。** 一切来自 `ray`、`uv` 和 `time`——没有贴图，没有外部绑定，帧与帧之间不保
  留状态。
- **所有运动都由 `time` 驱动。** 它是唯一的时钟，也是导出视频可复现的前提。
- **循环要小而固定。** 这段代码跑在一整个角色渲染的背后，每帧一次，最高 4K；五十次迭
  代是舒服的量级。导出会把开销乘上数千帧，所以某次导出异常地慢时，把特效设为 *None*
  再导一次，就知道有多少时间花在了它身上。
- **`fwidth` 只能用在一致的控制流里。** 基于 `fwidth` 的 `smoothstep` 能给出与分辨率无
  关的边缘，前提是相邻像素走了同一条分支——所以不要放在依赖数据的提前返回之后。
- **WGSL 的解析与顺序无关**，辅助函数可以写在 `background()` 下面。

## 2.4 材质着色图

着色图定义一个样式组的表面如何响应光照。它是 Blender 式的节点图——带类型的插槽用连线相
接——编译成 WGSL 并实时应用。

从 Materials 标签点开某组的着色图名称，**Browse all…**，再对任一条目选 **Edit
graph**。九个内置图——*Body*、*Eye*、*Face*、*Hair*、*Metal*、*Principled BSDF*、
*Rough Cloth*、*Smooth Cloth*、*Stockings*——就是参考实现。fork 一个：*Principled
BSDF* 是中性基底，其余八个是各类表面的范例。

### 节点面板

| 分类 | 内容 |
| --- | --- |
| **Input** | 表面自身的数据：贴图采样、几何（法线、视线方向、世界坐标与静止坐标、UV、反射）、材质自带的漫反射色、数值与 RGB 常量 |
| **Colour** | 色相/饱和度、亮度/对比度、反相，以及多种插值方式的颜色渐变——线性、常数、cardinal、抗锯齿常数、三角 |
| **Texture** | 程序化噪声与渐变 |
| **Vector** | 映射（位移/旋转/缩放）、bump、分离 XYZ、叉乘 |
| **Math / Mix** | 算术运算，以及按因子混合两个输入 |
| **Shader** | Principled BSDF、自发光、add/mix shader、shader-to-RGB、菲涅尔 |

最常打交道的插槽名是 `color`、`alpha`、`normal`、`view`、`uv`、`fac`（0–1 混合因子）、
`strength`、`roughness`、`metallic` 和 `base`。

### 搭建

- **添加节点**——在画布上右键，或用可按名称搜索的添加菜单。
- **连接**——从输出插槽拖到输入插槽，类型必须兼容。
- **未连接的输入使用其字面默认值**，可直接在节点上编辑。一张一条连线都没有的图同样是
  合法的图。
- **设定输出**——右键节点选 *Set as output*。这是材质真正渲染的值，每张图恰好有一个，
  且必须解析为颜色（`vec3f`）或标量（`float`）。
- **预览任意插槽**——*Preview output* 把某个插槽直接送到屏幕，单独看这一支产出了什么；
  *Stop preview* 回到真正的输出。这是编辑器里最有用的排查工具：图看起来不对时，从输出
  往回逐个预览插槽，第一个不对的地方就是问题所在。
- **Generated WGSL**——编辑器会显示这张图编译出的代码，当结果与预期不符时值得一读。

节点位置只是排版。挪动节点不会改变结果，重新排版过的图仍然算作与它来源的库条目完全
一致。

### MMD 的惯例

这个生态里的模型带着一些值得利用的约定：

- **Toon ramp。** MMD 模型自带把光照量化成色阶的 toon 贴图。标志性的赛璐璐观感，来自一
  条由法线与光线点积驱动的**常数**或**抗锯齿常数**颜色渐变——两到三个色阶，而不是平滑
  过渡。优先用抗锯齿的那一种，运动时更稳。
- **用菲涅尔做轮廓光。** 菲涅尔接自发光，再叠加到主着色上，就能得到那种「动画打光」的
  边缘分离感。强度要小，轮廓光只是一点提示。
- **眼睛需要自己的图。** 它比皮肤更平、更饱和、对场景光更不敏感，这正是 *Eye* 单独存
  在、以及眼睛样式组会被自动建立的原因。
- **头发需要各向异性。** 沿头发静止坐标做一条渐变去驱动高光，就能得到这种风格所期待的
  带状光泽。头发上均匀的镜面反射看起来像塑料。
- **丝袜等多层半透明材质**需要 alpha hashing 才能正确排序。内置的 *Stockings* 图及其组
  角色已经处理好了，自己做时从它开始。

一次只改一处，每改一次都回视口确认——出乎意料的结果，往往能追溯到三步之前的某条连线。
近景和远景都要看，因为在特写下调好的图，拉远可能变成一片噪点。还要记得开销是乘起来
的：一张图会在它所属组的每个材质的每个像素上、每一帧运行，所以同一张图用在占满画面的
服装上，代价远高于用在眼睛上。

## 2.5 草稿、发布与版本

三个创作面共用同一套生命周期。**编辑任何东西都会产生草稿**——内置内容原封不动，草稿私
有地存在你的浏览器里，可以随意重命名、继续改、拿去应用。**应用草稿是按值嵌入场景的**，
场景里携带的是调色、着色器或着色图的实体，这正是发布出去的场景能在别人机器上原样重现
的原因。

**发布**会铸出一个署你名字的库条目，所有人可见。由此有两个性质：

- **版本不可变。** 在自己的条目上再次发布，写入的是版本 *n+1*，而不是替换版本 *n*。所
  有在用旧版本的场景继续用它，一字不差。
- **场景锁定确切版本。** 场景记录的是 `{ id, version }`。你下个月重新调整这个预设，不
  会改变别人上个月用它发布的场景。

所以发布是一种承诺。放心地改进条目——版本机制就是为此存在的——同时已经发出去的那些版本
会继续为正在使用它们的人服务。

未经修改的内置内容走的是另一条路：场景只记录一个裸引用，由应用本身解析。这就是为什么
一个只用内置预设的场景，在没有网络、没有数据库的情况下也能正确渲染。

# 附录 C. 术语表

**ASC CDL**——美国电影摄影师协会 Color Decision List，Reze Design 调色背后的
slope/offset/power 颜色变换。

**借物表**——列出作品中用到的每一个模型、动作、特效与曲目及其作者的清单。发布时必填。

**骨骼（Bone）**——模型骨架上的关节。动作文件按名称寻址骨骼，这正是文件可互换的原因。

**赛璐璐着色 / toon shading**——把光照量化成平坦色阶而非平滑渐变，MMD 的标志性观感。

**等距柱状（Equirectangular）**——2:1 的全景投影方式，用于 skybox。

**调色（Grade）**——作用于整幅成品画面的颜色变换。

**MME（MikuMikuEffect）**——桌面版 MMD 的 DirectX 9 HLSL 特效插件。这里的对应物是背景
特效和着色图，用 WGSL 编写。

**变形（Morph）**——具名的形变目标，多为表情，由动作文件与骨骼一同驱动。

**PMX / PMD**——MMD 的模型格式，PMX 是现行标准。

**物理**——模型中定义、运行时模拟的头发、布料与挂件运动。

**着色图（Shader graph）**——定义表面如何响应光照的节点图，编译为 WGSL。

**样式组（Style group）**——共用同一张着色图的一组材质。

**利用規約**——模型的使用条款。发布前请阅读。

**VMD**——Vocaloid Motion Data，可能是身体动作，也可能是镜头动作。

**WebGPU**——本应用所基于的浏览器 GPU 接口。

**WGSL**——WebGPU 着色语言。背景特效用它编写，着色图编译为它。
