# Reze Design 使用手册

[English](https://github.com/AmyangXYZ/reze-design/blob/main/docs/manual/en.md) · **简体中文**

Reze Design 是一个跑在浏览器里的 MMD 场景工具：编排、渲染、发布。MMD 社区十几年攒下
的模型和动作，它拿来就能读，用 WebGPU 渲染，最后交给你一个视频文件，或者一个谁都能打
开、随手转动视角的实时页面。

**第 0 节**是背景，写给没接触过 MMD 的人。**第 1 节**从空场景讲到发布，是完整流程。
**第 2 节**讲怎么做出自己的风格：调色预设、用 WGSL 写的背景特效、用节点搭的材质着色
图。模型、动作和音乐去哪里找，见[附录 B](#附录-b-去哪里找模型动作和音乐)。

# 0. 关于 MMD

MikuMikuDance（**MMD**）是樋口優写的免费 3D 动画软件，2008 年 2 月发布，最早就是拿来
让初音未来跳舞的。真正长起来的是它周围那套**能自由拼装的生态**：模型是一个人做的一个
文件，舞蹈是另一个人做的另一个文件，运镜是第三个文件，它们之所以能拼到一起，只是因为
大家都守着同一套骨骼命名。一支成品 MMD 视频，背后常常是五到十五位素未谋面的作者。借
物表成为社区文化，2011 年的动作文件今天照样能用，根子都在这里。至于软件本身，是个
32 位、基于 DirectX 9 的 Windows 程序，开发在 2010 年代后期就停了，手机和平板更是无
从谈起。想要现代渲染的人只好转去 Blender 或 Unity：画面确实出色，但拼装性到导入那一
步就断了——转换过的资产、手工重搭的材质，别人已经拿不走了。

MMD 带起来的这套画风，如今早已进入主流。原神、深空之眼、鸣潮走的都是**三渲二**——把
3D 角色渲染出手绘动画的观感——每一部背后都是一个庞大的同人圈，二次创作产量惊人，其中
相当一部分至今仍靠 MMD 的模型和动作完成。让这套画风真正跑进浏览器的是 WebGPU；而在浏
览器这条路上，早就有人认真做过事：
[**babylon-mmd**](https://github.com/noname0310/babylon-mmd) 把 PMX 模型、VMD 动作、
物理和 MMD 兼容着色带进了 Babylon.js，至今仍是网页端 MMD 能做到什么程度的参照。
[**reze-engine**](https://github.com/AmyangXYZ/reze-engine) 选的是另一条路：不架在通
用引擎之上，而是专为 MMD 写一个渲染器。引擎之上有两个应用：**Reze Design**，也就是本
手册讲的这个，负责场景的设计、渲染和发布；以及
[**Reze Studio**](https://github.com/AmyangXYZ/reze-studio)，带时间轴、摄影表和贝塞
尔曲线编辑的动画编辑器。两者都只要一台装了现代浏览器的机器就能跑，直接吃生态里现成的
文件，并且把一个场景变成一条链接——别人点开就能转视角，也能接着往下做。

# 1. 做一个场景

## 1.1 整体流程

一个场景基本是一口气做完的。顺序没那么要紧，要紧的是每一步都能回头：所有设置一直是活
的，导出之前什么都没有定死。

> 载入模型 → 给它动作 → 加音乐 → 定镜头 → 打光 → 选风格 → 导出视频，或发布场景。

本节就顺着这条线走。一看就懂的控件——选文件、点色块、按播放——不再啰嗦，
[附录 A](#附录-a-控件速查) 里有每个控件和它的取值范围。

浏览器需要支持 WebGPU：Chrome / Edge 113 以上，或 Safari 26 以上。编辑器说启动不了，
基本都是这个原因。整个过程不上传任何东西，文件就待在这个标签页里，直到你自己按下
发布。

## 1.2 模型、动作、音乐

打开 **Assets** 载入模型：既可以选包含 `.pmx` 的整个文件夹，也可以直接选下载来的
`.zip`，两种都支持拖进来。

| 格式 | 是什么 |
| --- | --- |
| `.pmx` | 模型：网格、材质、贴图、骨骼、物理 |
| `.pmd` | 早期模型格式，请先用 PMX Editor 转换为 PMX |
| `.vmd` | 关键帧。同一个扩展名既可能是**身体动作**，也可能是**镜头动作**，它们载入到不同的槽位 |
| `.fx` | MikuMikuEffect 的 DirectX 9 特效。这里对应的是[背景特效](#23-用-wgsl-写背景特效)和[着色图](#24-材质着色图)，用 WGSL 编写 |

**别把模型文件夹拆开。** PMX 是按相对路径找贴图的，单把 `.pmx` 拎出来载入，模型就是白
的或灰的。这是新手最常踩的坑。

把身体动作载进同一个槽位，播放条就出来了，按播放即可。再加一个模型，它有自己的槽位和
自己的动作，镜头、灯光、风格则是全场共用一套。音乐挂在时间轴上，拖进度、开循环，声音
都跟着走。动作是照标准骨骼写的，所以谁都能驱动——体型差得多时会看到脚下打滑或者悬空，
换一个身材更接近原作者所用模型的角色就好了。

头发和裙摆走物理模拟，跳转之后要几帧才稳得下来。这段抖动不会进到导出文件里：导出器会
先渲一段预热，再开始录。

## 1.3 镜头

左键拖动旋转，右键拖动平移，滚轮缩放。

公开发布的舞蹈动作，大多还附一份**镜头动作**——另一个 `.vmd`，里面是编舞者自己的运
镜。载进 **Assets → Camera**，画面就完全照作者的设计走，鼠标这时不起作用；想自己看看
的话，播放条上的开关随时把控制权还给你，播放也不会中断。

要手动构图，**Scene → Camera** 比鼠标准得多。最常动的是 Target Y：角色身高大约 10 个
单位，所以目标高度取到 10 上下是脸部特写，5 上下是半身，取 0 就是贴地仰拍。

## 1.4 灯光

灯光分三块，真正要拿主意的地方不多。

**Sun** 是主光。阴影贴图跟它同一个方向，所以明暗和投影永远对得上。最出效果的是
**Elevation**：压低了，投影拉长，轮廓分得开；抬高了，人物变平，投影几乎缩没。

**World** 是环境补光，管的是太阳照不到的地方。强度调到 0，背光面全黑；调太高，画面发
平。多数风格是冷环境配暖主光，或者反过来——主光和补光之间的**色彩反差**，比谁的强度大
更管用。

**Bloom** 是高光溢出。强度 0 就是关，这时整个 pass 直接跳过。阈值接近 1.0，只有真高光
才发光；压到 0.3 上下，整幅画面都会起雾，这是很重的一种取向，用不用心里要有数。

**Ground** 有一点值得单说：不透明度只淡化地面，阴影还留着。把不透明度归 0、阴影开着，
就是一块「影子接收板」——影子浮在背景上，没有地面去跟照片背景抢戏。

## 1.5 角色背后的层

从后往前一共四层。最底下是**背景色**；往上是 **backdrop**（平铺在场景之后的一张图）
或者 **skybox**（2:1 等距柱状全景，投成无限远的天穹，随镜头转动，转视角就像望向真实
环境）；最上面是**背景特效**——夹在背景和角色之间画的一段着色器：雨、星、落樱、极光。

到 **Scene → Background** 里挑一个，或者打开库看全部。想自己写，见
[§2.3](#23-用-wgsl-写背景特效)。

## 1.6 风格

决定画面观感的有两套东西，作用的尺度不一样。

**调色预设**处理的是整幅成品画面，在灯光之后、导出之前。「渲染出来了」和「看着对了」
之间的那点差别，就在这里：同一个场景，调暖调亮是夏日午后，调冷再压一压暗部就成了夜
晚。**Scene → Grade** 里有内置的几套——*Neutral*、*Bloody*、*Cyberpunk*、*Divine*、
*Moonlit*、*Sakura*——强度滑杆是**按预设分别记的**，来回试几种再切回来，还是你上次为它
定的那个强度。想自己做，见 [§2.2](#22-调色预设)。

**样式组**决定表面怎么响应光照。这套概念 MMD 里没有：

> **样式组**是一组共用同一种外观的材质，**着色图**是定义这种外观的程序。每个样式组恰
> 好使用一张着色图。

一个 PMX 模型少则十几个材质，多则六十来个：脸一个、头发一个、衣服好几个。一个个调根本
没法忍，所以载入时会按名字和属性自动归组——头发归头发组，眼睛归眼睛组，皮肤归身体组。
遇上结构特别的模型难免归错，**Materials** 标签就是改这个的：把材质拖到别的组、新建一
组、把多余的挂件藏掉，或者给某一组换一张着色图。

有两处行为要留意。一是当某组的着色图和它来源的库条目对不上时，会打上 **edited** 标
记；这份差异随场景一起走，所以发布出去的场景能原样重现你做的东西。二是有些组带
**角色（role）**，管的不只是着色——头发和眼睛走专门的 pass，丝袜用 alpha hashing 才能
在多层叠加时排对顺序。角色是推断出来的，头发组和布料组表现不同就是这个缘故。

想一个节点一个节点地搭着色图，见 [§2.4](#24-材质着色图)。

## 1.7 导出

**Render** 标签里定画幅和画质，从 2.39:1 宽银幕到竖屏 9:16，最高 4K；也可以只导一
段，比如 `0:12` 到 `0:30`。这个标签打开着的时候，视口上会叠一层取景预览：框住的就是要
录的东西。

**Render video** 输出 60 fps 的 H.264 MP4。Chromium 桌面端会先让你选保存位置，然后边
编码边往文件里写，所以再长的 4K 也不用整个塞进内存。

导出器有两点值得知道。一是它**离线**逐帧渲染，所以导出质量跟你的显示器无关，跟标签页
在不在前台也无关——机器慢，出来的文件一模一样，只是等得久些。二是录下来的就是你眼前的
镜头、灯光和调色，不存在第二套要另外同步的渲染设置。

**Capture PNG** 按同样的画幅和分辨率写出单帧，水印和绿幕设置照样生效。它抓的就是屏幕
上这一帧的姿势，不跳转也不重置，没有动作也能用——发布场景要的封面图，就靠它。封面建议
用 1080p 抓：细节多的场景在 4K 下容易超过 20 MB 上限。

**Green screen** 把背景换成纯 `#00FF00`，方便在别处合成，也就是 MMD PV 的经典流程。

## 1.8 发布

发布会把你的场景变成一个谁都能打开的页面：一份能自由转视角的实时渲染。

按 **Share** 之前，先确认你有没有权利分享。几乎每个模型的下载包里都附着一份**利用規
約**，其中**「再配布禁止」——禁止二次分发——非常常见**。发布要把你载入的模型、动作和音
频打包上传，场景才能在别人的浏览器里渲染出来，而这在多数条款下就算二次分发。导出视频
是另一回事：视频里没有模型文件。条款通常还会写到改造、R-18 表现、政治宗教用途和
商用。

条款之外还有社区自己的规矩——**借物表**：把用到的每一个模型、动作、特效、曲目连同作者
一并列出来，观众顺着它就能找回原作者。Reze Design 要求必填：

```
模型：Tda式初音ミク・アペンド by Tda / 改造 by …
动作：… by …
镜头：… by …
音乐：… by …
```

借物表之外，对话框还要名称、简介、最多五个标签和一张封面图。进度按阶段报——打包、上
传、发布——失败时会告诉你卡在哪一步、具体是什么原因。填的文字随输入保存，所以中途跑去
截封面图，回来简介还在。

最后得到一条 `reze.design/<你的名字>/<id>` 的永久链接。真正拿来解析的是那个短 id，所
以之后改场景名、甚至改你自己的名字，已经发出去的链接都不会失效。

## 1.9 画廊

Scene 标签下方的画廊按钮，打开的是所有人发布过的场景，可以按热门、最新、最赞、我的、
已赞浏览，并用标签筛选。

在某个场景的页面上可以转视角、播放、点赞。**Open in editor** 把整个场景搬进你的编辑
器，成为**你自己的一份副本**：模型、动作、灯光、调色、材质分配全在，接着往下做就行。
副本是独立的，发布它只会新建一个场景，原作动不了。借物表也会一并带过来，在它基础上继
续补。

账号存在的意义，就是让你拥有自己发布的东西。首次登录要**给自己定个名字**，它会出现在
你创建的每一条场景链接里，而且**只能定一次**——正因为不可改，分享出去的链接才能一直
有效。

## 1.10 出问题时

**模型是白的、灰的或黑的。** 贴图没找着，几乎都是因为只载入了 `.pmx` 本身。请载入整个
文件夹，或者原始的 `.zip`。

**模型载不进来。** 先看是不是 `.pmd`——旧模型得用 PMX Editor 转成 `.pmx`。

**动作在播，模型不动。** 动作载到别的模型槽位上去了；也可能是这个模型的骨骼命名不合标
准约定——从别的游戏转过来的模型常有这毛病。

**脚下打滑，或者陷进地面。** 模型的比例和动作原作者用的那个对不上。

**镜头不听使唤。** 有镜头动作正驱动着它，在播放条上切回自由视角就行。

**导出有点慢。** 它在离线逐帧渲染：一段三分钟的 4K，就是几千张全画质图。平时迭代用
1080p 导一小段，定稿了再走一遍 4K。

**发布失败。** 报错会写明卡在哪一步：*打包*多半是少了某个资源；*上传*多半是包体超过
200 MB 或者网断了；*发布*多半是登录过期，或者名字撞了。

# 2. 做出自己的风格

三个可创作的地方，分别位于同一条管线的三个层级。先学哪个都行。

## 2.1 渲染管线

先弄清你写的东西到底作用在哪一层，后面的大半内容就顺理成章了。从镜头往里看，由后
到前：

```
  背景色  →  backdrop / skybox  →  背景特效 (§2.3)
                                        ↓
                                  角色，由样式组各自的
                                  材质着色图 (§2.4) 着色
                                        ↓
                                      bloom
                                        ↓
                                  调色预设 (§2.2)
                                  作用于整幅画面
                                        ↓
                                  屏幕、视频、PNG
```

所以：

- **背景特效**在角色后面，角色直接盖在它上面。
- **着色图**只管一个模型上的一个样式组，能用的是这个表面自己的数据：贴图、法线、视线
  方向。
- **调色预设**最后才作用，均匀地摊到每一个像素上，那时画面已经成型了。

三者都**写在场景文档里面**，所以发布出去的场景能原样重现你的风格，对方有没有你用过的
预设都一样。

## 2.2 调色预设

调色走的是 **ASC CDL**：美国电影摄影师协会那套 Color Decision List，影视后期就靠它。
三个色调区间，每个区间各有 slope、offset、power，实际操作时用色轮。这套说法跟别的调色
工具是通的，学会了两边都能用。

### 编辑器

打开调色库，把鼠标停在某个预设上选 **Edit**；或者直接从 **Scene → Grade** 编辑当前用
着的这套。编辑器背后就是预览——每动一下都实时落在你自己的角色、你自己的光上。判断一次
调色成不成立，只有这一个靠得住的办法。

**Split tone**（−1 到 +1）放在最前面是有意的：单看一个动作，它最能表达调色意图，让暗
部和亮部沿冷暖轴往相反方向拉。负值是冷暗部配暖亮部，也就是现代电影那套「青橙」；正值
反过来，暖暗部配冷亮部，看着像烛光、像日落、像回忆。

**三个色轮**——shadows、midtones、highlights——分别控制三个色调区间：

- **角度**——该区间偏向的色相。
- **离中心的距离**——偏移的程度。
- **色轮旁的滑轨**——该区间的明度。把暗部滑轨往下拉就是压黑，把亮部滑轨往上推就是
  提亮。

**Contrast**（0.5 – 1.6）以中灰为轴，**Saturation**（0 – 2）缩放色彩浓度，0 为黑白。

### 工作方法

按这个顺序来，结果最可控：

1. **先把灯光弄对。** 调色是在光给的底子上加东西。人物看着发平，先去调太阳仰角和环境
   光强度，别急着动调色。
2. **定 split tone**，然后停一下。很多时候这一下就是整个调色了，后面全是修饰。
3. **先用滑轨压黑提亮，再推色相。** 明暗比色彩显眼，也框住了色彩能走多远。色相一次只
   推一个区间，而且要比你以为的更收着点：色轮推到一半，风格已经很足了。
4. **饱和度留到最后**，通常还是往下压；判断的时候把强度开到 1，回头再去 Scene 标签定
   你真正想要的强度。半强度下调色，容易一路调过头。

有两个习惯很划算。一是**常跟 Neutral 比一比**：看久了什么都会变正常，切到 Neutral 停
两秒，这次调色值不值得留下就清楚了。二是**照导出分辨率来调**——小窗口里看着合适的
bloom 阈值，到 4K 可能一碰就发光。

### 保存与分享

编辑预设会生成一份你自己的**草稿**，存在本地浏览器里，可以改名、接着改、随便用到多少
个场景上。草稿是私有的，不会离开你的机器。

**Publish** 把草稿变成一个署你名字的库条目，所有人可见。这一步意味着什么，见
[§2.5](#25-草稿发布与版本)。

## 2.3 用 WGSL 写背景特效

背景特效是一段着色器，画在背景和角色中间那一层。雨、雪、星空、极光、流动的渐变、一张
标题卡——只要能靠视线方向和时间逐像素算出来，就能画。

库里有五个写好的范例，各演示一种做法：*Shining Stars*（哈希网格粒子场）、*Quiet
Rain*（列状拖尾）、*REZE DESIGN*（SDF 字形配指数辉光）、*Orbiting Hearts*（隐函数曲线
描边）、*Fuji Watercolor*（分层水墨构图）。想入门，读它们最快。

### 契约

一个函数，这就是全部接口：

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f
```

| 参数 | 含义 |
| --- | --- |
| `ray` | 该像素的世界空间视线方向，已归一化。它**随镜头转动而移动**，因此由它算出的东西是钉在世界上的，而不是钉在屏幕上 |
| `uv` | 屏幕坐标，0 – 1，原点在**左下角** |
| `time` | 特效应用后经过的秒数 |

返回值是 **sRGB 颜色 + 直通 alpha**。关键在 alpha：它是盖在你身后那一切之上的遮罩。

- `alpha = 0`——透明，背景色、backdrop 或 skybox 透出来。
- `alpha = 1`——不透明，你的特效取代它身后的一切。

**叠加型**的特效——雨、花瓣、火星——笔触之间把 alpha 压在 0 附近，只在落笔的地方抬起
来。**全屏型**的——渐变天空、整幅背景——则处处返回 alpha 1。

### 两种取向

用 `ray` 还是用 `uv`，是第一个要定的事，它决定了镜头一动特效会怎么表现。

**屏幕空间**，来自 `uv`：钉在画框上。镜头看向哪儿，雨都照样沿着屏幕往下落。天气、暗
角、颗粒，以及一切概念上处在世界**前面**的东西，都该这么写。

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  // 修正宽高比，让圆是圆的。
  let res = bgResolution();
  let p = (uv - 0.5) * vec2f(res.x / res.y, 1.0);
  let d = length(p);
  let vignette = smoothstep(0.8, 0.2, d);
  return vec4f(vec3f(0.02, 0.03, 0.08), 1.0 - vignette);
}
```

**世界空间**，来自 `ray`——属于环境的一部分。转动镜头它待在原处，就像真实的天空。用与
skybox 相同的映射把视线投到球面坐标：

```wgsl
fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  // 经纬度——skybox 自己的投影方式。
  let sky = vec2f(atan2(ray.x, ray.z), asin(clamp(ray.y, -1.0, 1.0)));
  let band = smoothstep(0.0, 0.35, sky.y);          // 地平线 → 天顶
  let dusk = mix(vec3f(0.85, 0.45, 0.30), vec3f(0.06, 0.09, 0.22), band);
  return vec4f(dusk, 1.0);
}
```

这一步要想清楚。拿 `uv` 画的星星，镜头一转就整片跟着滑过天空；观众未必说得出哪里不
对，但一眼就看得出不对。

### 一个完整的叠加例子

飘浮的光点，使用起始模板里的哈希辅助函数：

```wgsl
const COUNT: i32 = 48;
const FALL_SPEED: f32 = 0.04;
const RADIUS: f32 = 0.006;

fn background(ray: vec3f, uv: vec2f, time: f32) -> vec4f {
  let res = bgResolution();
  let p = (uv - 0.5) * vec2f(res.x / res.y, 1.0);

  var acc = 0.0;
  for (var i = 0; i < COUNT; i = i + 1) {
    // 每个光点一个稳定的伪随机初始位置。
    let seed = hash2(vec2f(f32(i), 7.0));
    // 下落、到底回绕，并按各自的相位横向漂移。
    let y = fract(seed.y - time * FALL_SPEED) - 0.5;
    let x = (seed.x - 0.5) * 1.8 + sin(time * 0.6 + seed.x * 30.0) * 0.02;
    let d = length(p - vec2f(x, y));
    // 按比例衰减，任何分辨率下边缘都保持清晰。
    acc = acc + smoothstep(RADIUS, 0.0, d);
  }

  let glow = clamp(acc, 0.0, 1.0);
  return vec4f(vec3f(1.0, 0.94, 0.82), glow * 0.85);
}
```

几个写法值得留意：可调的量都写成文件顶部具名的 `const`；用 `fract` 让运动回绕，长镜头
下才不会越积越大；边缘一律交给 `smoothstep`。

### 编辑循环

打开 **Scene → Background → Library**，点 **New effect** 拿一份带注释的起始模板；或者
右键任意预设选 **Edit shader**，从它 fork 一份。

**<kbd>⌘/Ctrl</kbd>+<kbd>Enter</kbd> 编译并应用。** 场景本身就是预览，没有单独的渲染按
钮，也没有预览窗口。编过了，特效立刻生效；没编过，先前那份着色器原样留着，同时给出报
错，`行:列` 已经对回你自己写的代码。所以怎么改都不会把自己改到一片黑屏。

### 规则

- **自包含。** 能用的只有 `ray`、`uv`、`time`：没有贴图，没有外部绑定，帧与帧之间也不
  留状态。
- **所有运动都由 `time` 驱动。** 它是唯一的时钟，导出的视频能复现，全靠它。
- **循环要小、要固定。** 这段代码跑在一整个角色渲染的背后，每帧一次，最高 4K；五十次
  迭代是舒服的量级。导出还要把这份开销乘上几千帧，所以哪次导出慢得反常，把特效切成
  *None* 再导一遍，就知道时间花在哪了。
- **`fwidth` 只能用在一致的控制流里。** 基于 `fwidth` 的 `smoothstep` 能给出跟分辨率无
  关的边缘，前提是相邻像素走了同一条分支——所以别放在依赖数据的提前返回后面。
- **WGSL 不管定义顺序**，辅助函数写在 `background()` 下面就行。

## 2.4 材质着色图

着色图规定一个样式组的表面怎么响应光照。它是 Blender 那种节点图：带类型的插槽，用连线
接起来，编译成 WGSL，实时生效。

从 Materials 标签点开某组的着色图名称，**Browse all…**，再对任意一条选 **Edit
graph**。九个内置图——*Body*、*Eye*、*Face*、*Hair*、*Metal*、*Principled BSDF*、
*Rough Cloth*、*Smooth Cloth*、*Stockings*——就是参考实现。挑一个 fork：*Principled
BSDF* 是中性底子，其余八个是各类表面的现成例子。

### 节点面板

| 分类 | 内容 |
| --- | --- |
| **Input** | 表面自身的数据：贴图采样、几何（法线、视线方向、世界坐标与静止坐标、UV、反射）、材质自带的漫反射色、数值与 RGB 常量 |
| **Colour** | 色相/饱和度、亮度/对比度、反相，以及多种插值方式的颜色渐变——线性、常数、cardinal、抗锯齿常数、三角 |
| **Texture** | 程序化噪声与渐变 |
| **Vector** | 映射（位移/旋转/缩放）、bump、分离 XYZ、叉乘 |
| **Math / Mix** | 算术运算，以及按因子混合两个输入 |
| **Shader** | Principled BSDF、自发光、add/mix shader、shader-to-RGB、菲涅尔 |

最常打交道的插槽名是 `color`、`alpha`、`normal`、`view`、`uv`、`fac`（0–1 混合因子）、
`strength`、`roughness`、`metallic` 和 `base`。

### 搭建

- **加节点**：画布上右键，或者用添加菜单，可以按名字搜。
- **连线**：从输出插槽拖到输入插槽，类型得对得上。
- **没连线的输入用它自己的默认值**，直接在节点上改就行。一条线都不连的图，也是合法
  的图。
- **指定输出**：右键节点选 *Set as output*。这就是材质真正渲染出来的那个值，每张图有且
  只有一个，而且必须是颜色（`vec3f`）或标量（`float`）。
- **预览任意插槽**：*Preview output* 把某个插槽直接丢到屏幕上，单看这一支算出了什么；
  *Stop preview* 回到真正的输出。这是编辑器里最好用的排查手段——图看着不对，就从输出往
  回一个个预览，第一个不对劲的地方就是问题所在。
- **Generated WGSL**：编辑器会显示这张图编译出来的代码，结果跟预期对不上时值得读一读。

节点摆在哪儿只是排版。挪动节点不影响结果，重新排过版的图，仍然算跟它来源的库条目一
模一样。

### MMD 的惯例

这个生态里的模型自带一些约定，顺着用比对着干省事得多：

- **Toon ramp。** MMD 模型本身就带把光照切成色阶的 toon 贴图。那种标志性的赛璐璐观感，
  来自一条由法线与光线点积驱动的**常数**或**抗锯齿常数**渐变——两三个色阶，不是平滑过
  渡。优先用抗锯齿那一种，动起来更稳。
- **轮廓光用菲涅尔做。** 菲涅尔接自发光，再叠到主着色上，就是那种「动画打光」的边缘分
  离感。强度给小一点，轮廓光点到为止。
- **眼睛得单独一张图。** 它比皮肤平、比皮肤饱和，对场景光也更不敏感——*Eye* 单独存在、
  眼睛样式组自动建出来，都是这个道理。
- **头发要各向异性。** 沿头发的静止坐标拉一条渐变去驱动高光，就能得到这种风格该有的带
  状光泽。头发上均匀的镜面反射，看着像塑料。
- **丝袜这类多层半透明材质**得靠 alpha hashing 才能排对顺序。内置的 *Stockings* 图和它
  的组角色已经处理好了，自己做就从它起步。

改的时候一次只动一处，每改一次回视口看一眼——结果出乎意料，多半能追到三步之前的某条
线。近景远景都要看：特写下调好的图，拉远可能就是一片噪点。还要记着开销是乘起来的——一
张图会在它所属组的每个材质、每个像素、每一帧上跑一遍，所以同一张图，用在占满画面的衣
服上远比用在眼睛上贵。

## 2.5 草稿、发布与版本

三个地方共用同一套流程。**改任何东西都会先变成草稿**：内置内容原封不动，草稿私有地待
在你的浏览器里，随便改名、接着改、拿去用。**草稿应用到场景是按值嵌进去的**——场景里带
的是调色、着色器、着色图的实体，所以发布出去的场景才能在别人机器上原样重现。

**发布**会生成一个署你名字的库条目，所有人可见。由此有两条性质：

- **版本不可变。** 在自己的条目上再发一次，写进去的是版本 *n+1*，不会顶掉版本 *n*。还
  在用旧版本的场景照旧用它，一字不差。
- **场景锁死具体版本。** 场景记的是 `{ id, version }`。你下个月把这套预设重调一遍，也
  动不了别人上个月用它发布的场景。

所以发布是一种承诺。条目该改就改——版本机制就是为这个准备的——已经发出去的那些版本，会
继续伺候还在用它们的人。

没改过的内置内容走另一条路：场景只记一个裸引用，由应用自己解析。所以一个只用内置预设
的场景，断网、没数据库，照样渲染得出来。

# 附录 C. 术语表

**ASC CDL**——美国电影摄影师协会 Color Decision List，Reze Design 调色背后的
slope/offset/power 颜色变换。

**借物表**——列出作品中用到的每一个模型、动作、特效与曲目及其作者的清单。发布时必填。

**骨骼（Bone）**——模型骨架上的关节。动作文件按名称寻址骨骼，这正是文件可互换的原因。

**赛璐璐着色 / toon shading**——把光照量化成平坦色阶而非平滑渐变，MMD 的标志性观感。

**等距柱状（Equirectangular）**——2:1 的全景投影方式，用于 skybox。

**调色（Grade）**——作用于整幅成品画面的颜色变换。

**MME（MikuMikuEffect）**——桌面版 MMD 的 DirectX 9 HLSL 特效插件。这里的对应物是背景
特效和着色图，用 WGSL 编写。

**变形（Morph）**——具名的形变目标，多为表情，由动作文件与骨骼一同驱动。

**PMX / PMD**——MMD 的模型格式，PMX 是现行标准。

**物理**——模型中定义、运行时模拟的头发、布料与挂件运动。

**着色图（Shader graph）**——定义表面如何响应光照的节点图，编译为 WGSL。

**样式组（Style group）**——共用同一张着色图的一组材质。

**利用規約**——模型的使用条款。发布前请阅读。

**VMD**——Vocaloid Motion Data，可能是身体动作，也可能是镜头动作。

**WebGPU**——本应用所基于的浏览器 GPU 接口。

**WGSL**——WebGPU 着色语言。背景特效用它编写，着色图编译为它。
